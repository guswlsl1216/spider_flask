# S.P.I.D.E.R - Flask AI Server

설비 센서 데이터를 기반으로 다음 값을 예측하고  
위험 점수(danger_score)를 계산하는 AI 서버입니다.

본 프로젝트는 팀 프로젝트로 개발된 백엔드 서버를 기반으로,  
프로젝트 종료 이후 **모델과 위험 판단 기준을 개인적으로 보완한 버전**입니다.

---

## 1. 프로젝트 개요

최근 10개의 센서 데이터(온도, 습도, 소음)를 입력으로 받아  
LSTM 모델로 다음 값을 예측합니다.

예측 결과를 기반으로 위험 점수를 계산하고  
설비 상태를 다음과 같이 분류합니다.

- NORMAL  
- WARNING  
- STOP  

---

## 2. 프로젝트 종료 후 개인 개선 사항

### 2-1. 모델 보완 및 추가 학습

#### 기존 모델의 문제점
- 노이즈에 민감하여 예측값 변동이 큼
- 실제 운영 센서 데이터와 학습 데이터 간 분포 차이 존재
- 정상 상태에서도 WARNING이 발생하는 오탐 문제

#### 개선 내용
- LSTM 구조 일부 조정
- 활성화 함수 변경
- 손실 함수 변경
- 실제 운영 데이터를 반영하여 추가 학습 진행

수치적인 성능 향상 및 **정상 구간에서의 오탐 감소와 예측 안정성 개선**에 초점을 두고 보완했습니다.

---

### 2-2. 위험 점수 기준 조정

기존 기준:

```
EMERGENCY_TH = 70
WARNING_TH = 40
```

수정 후:

```
EMERGENCY_TH = 70
WARNING_TH = 60
```

WARNING 기준이 낮아 정상에 가까운 상태도 경고로 표시되는 문제가 있어 기준을 상향 조정했습니다.
모델 개선과 함께 위험 판단 기준도 함께 보완한 작업입니다.

---

### 2-3. 시뮬레이션 환경 구성

프로젝트 종료 후 Azure 운영 데이터가 정리되어  
실제 DB 기반 테스트가 어려워졌습니다.

이를 해결하기 위해:

- CSV 기반 센서 데이터(`test_simulation_data.csv`) 추가
- DB 없이도 모델 추론이 가능하도록 로직 분리
- GitHub에서 바로 실행 가능한 구조로 구성

로컬 환경에서 예측 흐름과 위험 점수 계산 과정을 확인할 수 있습니다.

---

### 2-4. 위험 점수 저장 로직 안정성 보완

위험 점수 저장 시 예외 상황을 고려하여:

- 트랜잭션 rollback 처리
- 예외 로그 기록
- 저장 실패 시에도 서버가 중단되지 않도록 처리

운영 환경을 고려한 안정성 보완 작업을 진행했습니다.

---

## 3. 실행 방법

### 1) 패키지 설치

```
pip install -r requirements.txt
```

### 2) 서버 실행

```
flask run
```

---

## 4. 프론트엔드 연동 안내

본 서버는 단독 실행 시 내부 로직은 동작하지만,  
예측 결과 및 위험 상태 확인을 위해서는  
S.P.I.D.E.R Frontend 프로젝트와 함께 실행해야 합니다.

- Frontend Repository: ([팀 프론트 레포 링크](https://github.com/betterproject-dev/spider_front))

프론트엔드를 함께 실행하면:

- 센서 데이터 흐름 확인  
- 위험 점수 변화 확인  
- 설비 상태 시각화 확인  

이 가능합니다.

## 6. 정리

이 프로젝트는 단순히 모델을 구현하는 것에서 끝나는 것이 아니라,  
실제 데이터 특성에 맞게 모델과 위험 판단 기준을 함께 조정해본 경험입니다.

프로젝트 종료 이후 개인적으로 개선 작업을 진행하며 오탐을 줄이고, 실행 가능성을 높이는 방향으로 보완했습니다.
